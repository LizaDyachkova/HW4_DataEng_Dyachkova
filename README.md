# ДЗ 4 Обеспечение отказоустойчивости средствами Apache ZooKeeper

Дьячкова Елизавета Александровна, группа J3212, ИТМО. Работа продолжает [ДЗ №3](https://github.com/LizaDyachkova/HW3_DataEng) и использует реализованные в ней правила отбора вакансий и нормализации навыков.

Весь код приложения написан на Python с Kazoo; Java 17 используется только самим сервером ZooKeeper.

Три сервера ZooKeeper 3.9.6, два координатора подсчёта пар навыков C#/.NET, сессия 10 секунд, общий чекпоинт, приостановка SIGSTOP и публикация с проверкой эпохи. Расчёт использует те же функции нормализации и отбора, что и ДЗ 3. Вместо S3 вход читается из исходного локального CSV; предмет вычисления — пары навыков, как требует ДЗ 4. Данные и общий каталог состояния должны быть доступны обоим координаторам на одном компьютере.

## Воспроизведение

Нужны Python 3.9+, Java 17 и ZooKeeper 3.9.6. Архив ZooKeeper: [Apache Archive](https://archive.apache.org/dist/zookeeper/zookeeper-3.9.6/). Распакуйте бинарный архив; путь к нему задаётся явно. Скрипт создаёт три копии ZooKeeper в `runtime/zk1`–`runtime/zk3`, независимые конфигурации, каталоги данных и `myid`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/configure.py "$JAVA_HOME" /absolute/path/apache-zookeeper-3.9.6-bin
python src/prepare.py /absolute/path/it_vacancies_2024.csv
python scripts/run_lab.py > logs/experiments.txt 2>&1
```

В `logs/` уже приложены фактические результаты выполненных опытов. Новый запуск создаёт отдельные каталоги для failover, но `logs/ensemble.txt` перезаписывается. Quorum-тест при повторе пересоздаёт только свой тестовый путь `/hw4/quorum`.

Для ручного запуска двух координаторов используйте одно уникальное имя расчёта `--run`, разные имена `--name` и одинаковый `--fencing`:

```bash
FENCING=1 python src/coordinator.py --run manual-001 --name A
FENCING=1 python src/coordinator.py --run manual-001 --name B
# В третьем окне: PID есть в JSON-журнале первого лидера
kill -STOP PID
# Дождаться публикации резервного, примерно 40 секунд
kill -CONT PID
```

`FENCING=0` демонстрирует две успешные публикации. `FENCING=1` отклоняет старую эпоху через `BadVersionError`. Оба режима защищают общий чекпоинт от старого лидера. Для воспроизводимого окна отказа после каждой партии из 200 вакансий добавлена пауза 0,8 с, она не меняет результат расчёта.

## Устройство

* `src/hw3_common.py` — правила отбора и нормализации из ДЗ 3, S3-функции удалены.
* `src/prepare.py` — полный проход исходного CSV и эталон всех пар.
* `src/coordinator.py` — выбор лидера через ephemeral sequential и watch предшественника; чекпоинты и публикация.
* `scripts/ensemble.py` — запуск, остановка и статус трёх серверов штатным `zkServer.sh`.
* `scripts/experiments.py` — кворум, CLI ephemeral, SIGSTOP/SIGCONT, замеры, автоматические проверки.
* `conf/1`–`conf/3` — фактически использованные конфигурации; `dataDir` пересоздаётся скриптом для текущего пути проекта.
* `logs/` — исходные журналы и итоговые JSON с замерами.
* Отчёт предоставляется отдельно.

В ZooKeeper находятся только метаданные: `/hw4/RUN/election`, `/epoch`, `/checkpoint`, `/result`, `/writes`. Большие счётчики сохраняются в локальном общем каталоге `state/RUN` в файлы с SHA-256 в имени. Файл полностью записывается и атомарно переименовывается до публикации указателя. Чекпоинт содержит позицию, все накопленные частоты и контрольную сумму.

Получатель результата — функция `publish`, которая работает в отдельной клиентской сессии. В режиме защиты она атомарно проверяет версию `/epoch` и обновляет `/result` вместе с записью аудита. Поля указателя содержат имя автора и SHA-256 неизменяемого файла результата. Это один логический получатель, реализованный через транзакцию ZooKeeper. Для внешней БД или S3 аналогичную проверку должен реализовывать именно внешний получатель, атомарно со своей записью.

Учебный сценарий намеренно позволяет устаревшему вычислителю завершить локальную работу и попробовать публикацию: так виден эффект fencing. В промышленном приложении потеря сессии также должна останавливать дальнейшее управление работой. Fencing нужен, поскольку остановка процесса сама по себе не гарантируется при GC-паузе или потере сети.

В репозиторий включён компактный производный вход `data/skills.jsonl` и эталон `data/baseline_pairs.json`. Поэтому после установки зависимостей можно повторить испытания без исходного CSV; для независимой перепроверки подготовки нужен оригинальный файл размером 847 619 384 байт с SHA-256 из `logs/prepare.txt`.
